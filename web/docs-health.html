How this site is tested

Every 15 minutes status.dliu.com checks this site as a guest (not signed in, no cookies): it opens the public pages and URLs, then reads /health, which reports whether each behind-the-scenes function is working.

Functions checked

FunctionWhat is checkedIf it is down
PagesThe dashboard and the docs pages open.Visitors cannot open traffic.dliu.com.
Public statisticsThe 7, 30 and 90-day totals guests see are refreshed every day.Guests see numbers stuck on an old day.
Page scriptThe page script the sites load, /t/s.js, downloads.The sites stop reporting time on page and clicks.
Microsoft sign-inSign in sends you to Microsoft, and private data stays locked without it.The owner cannot sign in to see the full dashboard; guests are not affected.
Request loggingThe log files CloudFront delivers for every site are filed as they arrive.New visits are no longer recorded, and the dashboard stops moving.
Bot checkThe bot check that runs every 6 hours finishes on time, and the hosting network list it uses is refreshed weekly.Bots get counted as people, so visitor numbers run high.

The site counts as down when Pages or Request logging fails; when another function fails it counts as degraded.

Technical details: the /health endpoint
  • GET https://traffic.dliu.com/health (HEAD also works), no sign-in.
  • CloudFront forwards no cookies, no Authorization header and no query string, and the handler reads none of them.
  • Cached 60 s at CloudFront (cache-control: public, max-age=60), so the checks run at most about once a minute however often it is requested.
  • Read only: one cheap read per dependency; no writes, no S3 LIST, no Athena query and no AbuseIPDB call.
  • Each check times out after 2 s; the whole response returns within 5 s.
  • Content-Type: application/health+json; HTTP 200 for pass or warn, 503 for fail.
  • output is only a short reason such as timeout, read failed or stale, with no names, counts or user data.

Technical details: rules for the tests
  • Requests are GET or HEAD only, with no cookies and the user agent dliu-status-bot/1.0 (+https://status.dliu.com/docs); traffic.dliu.com drops that user agent from its logs.
  • Never send POST to /t/e or /api/; the tests are read only and never change anything.
  • Don't follow the /auth/login redirect; check only its status and Location.
  • 只用 GET 或 HEAD，不带 Cookie，用户代理为 dliu-status-bot/1.0 (+https://status.dliu.com/docs)；traffic.dliu.com 会从日志中丢弃这个用户代理的请求。
  • 不要向 /t/e 或 /api/ 发送 POST；测试只读，从不改变任何内容。
  • 不要跟随 /auth/login 的跳转，只检查状态码和 Location。

What isn't tested

  • The signed-in dashboard: the Athena queries behind every widget are for the owner only.
  • The Check bots now button and the AbuseIPDB reputation lookups (they need a sign-in, and AbuseIPDB's free allowance is limited).
  • The page script's reports to /t/e: a test report would count as a real visit.
  • Completing the sign-in at Microsoft (it needs an assigned account).
  • The daily log merge and the monthly city database download are seen only indirectly: when they break, Public statistics or Bot check go stale.
